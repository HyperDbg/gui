So first you should do some first basic checkings to get some basic datas about the target.

- Run target = does it run = ok
- Now if the target runs we check whether the target did used a IAT redirection or not + direct API commands
  or not.So in many cases WL does not write real API commands of call and jump dword [addr] in the codesection 
  and in this case we have to fix them from direct commands jmp / call API xy to jmp / call dword [addr]; API.
  In other cases there are a mix of both,fixed commands and direct commands and in other cases there are all 
  commands already ok and pointing to the real IAT.
- Check where the IAT starts and end.

Now if you have found out this basic datas you can start to find the OEP so there is also a very simple way 
how you can do this.You just need to know which address in the IAT was filled at last or near at last.So for this 
you can first try to use the last address in the IAT and there you set a HWBP write dword and restart the app 
and run till this address was filled by WL with the API address or API redirected address.After this you only 
just set a mem BP access on codesection and run and you break very quickly in codesection direct at the OEP 
or near OEP = sub routine if WL used stolen OEP bytes.

So in the case that your target used stolen OEP bytes and you stop near at OEP then you can check the stack 
for the return address in [ESP].Follow the address and you see where it was called from [WL section].

00405DAC  PUSH EBX  ; Near OEP sub routine

what we already know is the jump address to WL VM which are used for the stolen routine.

How does TM WL get APIs to use them for itself?
---------------------------------------------------------------------------------
So TM WL used 2 diffrent ways to read system APIs.
1. Read APIs from the export table of a dll [most protector have to do it]
2. Call APIs directly via GetProcAddress API

So if you want to know which APIs does the WL will access then you just need to find the place where you 
can catch the API addresses.So you can do it if you directly access the kernel32.dll export table 
Number of Names VA of the dll and you can also hook the GetProcAddress API.So this is a good and simple way 
to find out which APIs WL does call and wanna use and also you can find out which AntiDebug API will used 
by WL.Hook and log them to get a full list of called APIs by WL.
